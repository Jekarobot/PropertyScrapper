# 07-10 · Map legend and no-location bucket

**Points:** 1 · **Stage:** 07 — Map and selection · **Owner lane:** web · **Depends on:** 07-02 · **Unblocks:** 07-14 (bubble counting contract)

## Goal

Add the map's bottom-left legend (how many buildings are drawn, what the dot sizes mean, how to zoom without the wheel) and turn the `No location (N)` group under the results list into a real, collapsible bucket of selectable rows for buildings without coordinates.

## Why this task exists

Two facts about the map are invisible without chrome: a bubble's size means a unit count (F7), and the wheel deliberately does not zoom (F8's scroll policy, 07-11) so the hint explains the modifier. Separately, rule F6 says a building with `lat: null` is never in the viewport but must always be listed somewhere — that "somewhere" is the no-location bucket, and it has to be selectable, because the left panel is how a visitor reads its units. Without this bucket, an unmapped building is silently missing from the product; the current placeholder group (05-17) lists the name but is not a control.

- 07-02 done: `MapView` renders one `CircleMarker` per building with coordinates, radius `8 + 4·sqrt(n)` clamped 8–22, the accent colours and the `bubble bubble-<id>` classes.
- 06-06/06-09 done: `BuildingRow` takes `{ building, selected, onSelect }` and renders `aria-current`; `ResultsList` renders the rows.
- 05-17 done: `App` renders `inView` in the list and a simple `No location (N)` group for `noLocation` (non-interactive placeholder rows); 07-09 done: selection is wired through `App`.
- 05-11 done: `splitByLocation` produces `noLocation`; the count is the length of that array, never a recount.
- `MapLegend.tsx` and `NoLocationGroup.tsx` do not exist; `MapView` has no overlay chrome.

## Test first (red)

1. `MapLegend.test.tsx::test_shows_the_number_of_buildings_on_the_map` — `visibleCount` 2 renders `2 buildings` (and `1 building` for 1, singular), in a container labelled for assistive tech (an `aria-label` such as `Map legend`); the count is the prop, never recomputed.
2. `MapLegend.test.tsx::test_dot_key_shows_the_1_5_and_20_unit_sizes` — the legend renders three dots with the numbers `1`, `5` and `20`, and each dot's size matches the F7 radius for that count (12, 16.94…, 22) — the key is generated by the same function the map uses, not a hand-written second table.
3. `MapLegend.test.tsx::test_scroll_hint_names_the_modifier_and_the_legend_sits_bottom_left` — the text `Use ⌘/Ctrl + scroll to zoom` is present verbatim (including the ⌘ glyph and the slash), and the legend's container carries the bottom-left positioning tokens; it is an overlay, not part of the page flow.
4. `NoLocationGroup.test.tsx::test_lists_one_row_per_unmapped_building_with_the_count` — three buildings, one with null coordinates: the toggle reads `No location (1)`, and exactly one `BuildingRow` renders that building's name; the rows are visible by default (07-14 counts three rows at load without interaction).
5. `NoLocationGroup.test.tsx::test_collapsing_hides_the_rows_and_an_empty_bucket_renders_nothing` — pressing the toggle flips `aria-expanded` and removes the rows; with an empty array the whole section including the toggle is absent (no `No location (0)`).
6. `NoLocationGroup.test.tsx::test_clicking_a_row_selects_that_building` — a row click calls `onSelect` once with the building id; the component takes no bbox or map callback, so it cannot move the map.
7. `MapView.test.tsx::test_legend_receives_the_number_of_mapped_buildings` — with the fixture's three buildings (two with coordinates), the mocked legend receives `visibleCount` 2; the unmapped building is not counted, because it is not drawn.
8. `App.test.tsx::test_selecting_from_the_no_location_bucket_fills_the_panel_and_does_not_move_the_map` — click the bucket's row for `no-location`: the panel shows that building, and the mocked `MapView`'s `onViewportChange` was never invoked (selection must not recentre the map).

## Implement (green)

- `MapLegend` props `{ visibleCount: number }`. Renders the count with the building pluralisation the project already uses (reuse the helper 06-10 introduced; if it is still local to `ResultsList.tsx`, extract it to `lib/format.ts` with its own test and update the import — one pluraliser, recorded in `## Decisions`). Then the dot key and the scroll hint. One `aria-label` on the container; the dots are `aria-hidden` decoration with visible numbers beside them.
- The dot key sizes come from the same radius function as `MapView`: export it from one module (a small `lib/bubble.ts` is acceptable if exported and tested through both callers) or keep it in `MapView.tsx` and import it — never a second table of 12/16.94/22.
- `NoLocationGroup` props `{ buildings, selectedId, onSelect }`. A toggle button reading `No location (N)` with `aria-expanded` and `aria-controls`, expanded on first render; a list of `BuildingRow`s (the same component the results list uses) passing `selected` and `onSelect`. No map import, no bbox prop, no `onViewportChange`.
- `MapView`: render the legend component inside the map's relative container, handing it the count of buildings with both coordinates.
- `App`: replace the 05-17 placeholder group with the new component, passing `noLocation`, `selectedId` and `select`. The bucket stays under the results list and inside the same results region.

Run the two target suites, then `pnpm -C web test --run` — all green.
